---
title: 流れ
description: 取込から記録まで、patchiri が各段階で何をするか
---

patchiri の流れは、取込 → 検証 → 差分 → 承認 → 反映 → 記録 です。画面でも CLI でも同じコアを通るので、結果は変わりません。

## 1. 取込

Excel（`.xlsx`）、CSV、表への貼り付けで受け取ります。1 行目が列名（DB の列名）で、キーの列と変える列だけあれば足ります。列の順は自由で、貼っていない列は変わりません。

表への貼り付けや Excel が保存した CSV は、セルの値ではなく**表示された文字列**で届きます。そこで `2024/4/1`、`¥1,200`、`令和6年4月1日` のような Excel の表示の形も読み替えて受け付けます（[Excel の表示のままの値](/usage/excel/)）。

## 2. 検証

サーバの `describe` でテーブル定義を受け取り、全部のセルを確かめます。

- **DB の定義から**: 型、桁（文字数・バイト数、数の精度）、NOT NULL、主キーの重複、外部キーの参照先にあるか
- **業務ルールから**: 範囲、正規表現、使ってよい値、今の値からの変動率など（[業務ルール](/usage/rules/)）

誤りはセルの位置（`B3` など）と理由で示します。画面では赤いセルになり、直すと印が消えます。誤りがあるうちは差分を作りません。

## 3. 差分

キーで今の DB の値を読み（`fetch`）、行ごとに分けます。

| 状態 | 意味 |
| --- | --- |
| 変わる | どれかの列の値が今の DB と違う。反映の対象 |
| 同じ | 全部の列が今の DB と同じ。反映しない |
| キーなし | DB にそのキーの行がない。反映しない（UPDATE だけなので） |

差分は列ごとの「前」と「後」を並べた表で、CSV にも保存できます。これがそのまま承認資料になります。

## 4. 承認

patchiri の外で行います（メール、稟議など）。画面では差分 CSV と反映計画（`plan.json`）を保存でき、承認の後に CLI でその計画を反映することもできます。

## 5. 反映

反映は 2 段です。

1. **DB で確かめる**（`check`）: DB は変えずに、差分どおりに反映できるかをサーバが確かめます。実行する SQL も受け取れます。
2. **反映する**（`execute`）: 1 トランザクションで流します。

どちらも、サーバは対象の行にロックを掛けて今の値を読み、差分を取ったときの値（`before`）と比べます。1 行でも変わっていたら、何も反映せずに止まり、どの行のどの列が変わっていたかを返します。値の比べ方は厳密で、大文字小文字・かな・全角半角・末尾の空白も区別します（[API 仕様 1.6](/reference/api-spec/#16-比べ方行を探すときと値が変わっていないかを確かめるとき)）。

同じ反映を二度押ししても、反映は一度だけです（`requestId` で見分けます）。

## 6. 記録

反映すると、次のものが残ります。

- **実行した SQL**: 値を埋め込んだ、人が読める SQL。`check` で受け取った SQL を後から人が流しても、1 行でも見つからないか値が変わっていれば全部取り消して止まる形です。
- **戻し SQL**: 「今の値が patchiri で入れた値のままの行だけ、前の値に戻す」SQL。後から別の人が直した行は飛ばします。
- **反映ログ**: サーバ側に、誰が・いつ・どの行を・前後の値・メモを JSON Lines で残します。
