patchiri（パッチリ）は、自社開発の業務システムで「マスタを Excel の内容で一括更新する」作業を、ひとつの道具にまとめたものです。

## 困りごと

マスタの一括更新は、たいてい次のような手作業です。

1. 依頼者から更新内容の Excel を受け取る
2. 型・桁・存在しないコードなどを目で精査する
3. UPDATE 文を手で書く
4. 変更前後のエビデンスを取って承認をもらう
5. SQL を流す

いちばんつらいのは 2 の精査です。パッケージ製品には一括取込の機能があっても、自社開発のシステムにはないことが多いので、毎回人が見て、人が SQL を書いています。

## patchiri がすること

- **取込**: Excel、CSV、表への貼り付けで受け取る
- **検証**: DB のテーブル定義（型、桁、NOT NULL、主キー、外部キー）と、設定した業務ルールで全行を確かめ、誤りのセルを示す
- **差分**: 今の DB の値と並べ、「変わる」「同じ」「キーなし」に分ける。これがそのまま承認資料になる
- **反映**: 1 トランザクションで流す。差分を取った後で DB の値が変わっていたら、何も反映せずに止める
- **記録**: 実行した SQL と、戻し用の SQL、反映ログを残す

UPDATE 文は人が書きません。サーバが許可リストと照合して、パラメータ付きの UPDATE を自分で組み立てます。

:::tip[触ってみる]
[デモ](/demo/)では、ブラウザの中で動く PostgreSQL を相手に、貼り付けから戻し SQL まで一通り試せます。
:::

## 構成

```
 ブラウザ / CLI                                   サーバ（API 3 本だけ）
┌──────────────────────────────┐   describe     ┌────────────────────────────┐
│ 画面（表に貼り付け）         │ ─────────────▶ │ 許可リストと照合            │
│ CLI（Excel / CSV 取込）      │   fetch        │ パラメータ付き SQL を組む   │──▶ DB
│   └ コア: 取込・検証・差分   │ ─────────────▶ │ 変更前の値をトランザクション│
│                              │   apply        │ の中で確かめて反映          │
└──────────────────────────────┘ ─────────────▶ └────────────────────────────┘
```

- **コア**（`patchiri-core`）は TypeScript で、ブラウザでも Node でも動きます。取込・検証・差分はここで行います。
- **サーバ**に求めるのは、DB に触る API 3 本（テーブル定義、現在値、反映）だけです。仕様を決めてあるので、中身はどの言語でも作れます。参考実装は Node 版、C# 版、VB.NET 版があり、C# 版と VB.NET 版は既存の ASP.NET WebForms のアプリに WebMethod として足せます。
- **画面**（`patchiri-web`）は [spreadsheet-grid](https://www.npmjs.com/package/@ishibashi0112/spreadsheet-grid) を使った React の部品で、Node 版サーバが配るほか、ほかの React アプリにも埋め込めます。

## 安全のための約束

- 反映の API に SQL は渡しません。サーバが許可リストのテーブル・列と照合し、値はすべてパラメータで渡します。
- 「変更前の値から変わっていないか」はサーバがトランザクションの中で確かめます。画面の差分は承認資料であって、安全の根拠にはしません。
- 戻し SQL は「今の値が patchiri で入れた値のままの行だけ戻す」形です。後から別の人が直した行は上書きしません。
- データはブラウザとそのサーバの間だけを行き来し、外部には送りません。テレメトリもありません。

## 今できること

- DB: SQL Server、Oracle、PostgreSQL、MySQL / MariaDB（Node 版サーバ）。C# 版と VB.NET 版は SQL Server だけ。
- 1 回に 1 テーブル、UPDATE だけ。INSERT・DELETE と複数テーブルは、仕様に足せる形で残してあります（[構想の 9 章](/reference/concept/#9-まだ決めていないこと)）。
- 入口は画面（表への貼り付け）と CLI（Excel / CSV 取込）。

## 名前について

patchiri（パッチリ）は、patch と日本語の「ぱっちり」を合わせた名前です。旧名は harikit です。
